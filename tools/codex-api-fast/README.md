# Windows API Fast 可选补丁

部分 Codex Windows 版本会对 API Key 登录隐藏 Fast 入口。本工具在用户自己的
官方客户端副本中放开界面和请求的两处认证判断；仍遵守模型档位和
`fast_mode=false` 管理限制。实际加速与计费由 API 服务商决定。

这是可选的本地兼容补丁，默认不安装。不提供 API Key、额度或服务商权限。
仓库和分发包只包含补丁源码，不包含 OpenAI 客户端二进制。

## 安装

需要已安装的官方 Windows 商店版 Codex、Windows PowerShell 5.1，以及 PATH 中
可用的 Node.js 22 或更高版本和 npm。在本目录执行：

```powershell
npm ci
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-LocalApiFastClient.ps1
```

Node 不在 PATH 时，可给安装脚本传 `-NodePath <node.exe 的绝对路径>`。
依赖仍需先由 npm 安装。安装无需管理员权限，会额外占用一份客户端的磁盘空间。

### 自动重建与已知结构适配

安装 Node.js 22+ 并在本目录执行 `npm ci` 后，只需开启一次：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Enable-LocalApiFastAutoUpdate.ps1
```

也可指定 `-NodePath` 和 `-ModulePath`（包含 `acorn` 的 node_modules 目录）。
开启时记录这两个本机路径，不需要把 Node 加入桌面进程的 PATH，也不会自动下载或执行网络脚本。
以后从桌面切换器使用 API 账户时，先检查官方版本和副本完整性；需要适配时自动构建、校验并启动。
首次更新后的启动会较慢，后续复用通过验证的副本。个人账户不触发自动适配。

自动流程使用语义匹配，支持已知的 Fast 判断结构及变量、文件名变化。
它无法保证任意未来版本都兼容；遇到未知逻辑会停止修改、记录原因，并通过切换器提示降级到官方版。
相同包与补丁工具的失败只尝试一次，更新官方包、补丁工具或恢复依赖后自动重试；也可再次运行开启脚本手动重试。
诊断位于 `%USERPROFILE%\.codex-api-fast-client\auto-update-status.json`。

安装到 `%USERPROFILE%\.codex-api-fast-client\versions`。这里刻意避开 AppData：
在商店应用内写入 AppData 会被重定向到私有 LocalCache，桌面切换器无法看见。

退出 Codex 后，从本项目的 `Start.cmd` 或桌面切换器选择 API 配置档，
客户端便优先加载通过检查的副本。模型需要声明 Fast 档位支持。
从开始菜单直接打开官方商店应用仍使用原版。

## 更新失效问题与 agent 逐版本适配

### 问题：按钮可见不等于请求启用了 Fast

在已检查的官方版本中，API Key 登录受到两处独立判断约束：界面判断是否允许选择
Fast，请求准备逻辑再判断是否保留所选速度档位。只改按钮的显示条件，仍可能在发送前
丢掉 `priority`。本补丁给两处已确认的认证名单加入 `apikey`，让请求沿客户端原有流程
传递 Fast 档位；模型档位支持与 `fast_mode=false` 等限制继续生效。

实际提速由 API 服务商决定。按钮出现、请求携带 `service_tier: "priority"` 和服务端
实际加速是三个不同的验证结果，不能用其中一个代替其余两个。

### 为什么不能保证所有更新自动兼容

本项目的“自动适配”指自动检测版本、匹配已知代码结构、重建并校验副本，
不包含自动调用 agent 分析未知版本。语法树匹配可容忍已支持形式中的变量名、文件名等变化；
权限函数拆分、返回值改变、认证名单扩展等语义变化，可能需要维护者或 agent 更新规则。

| 遇到的情况 | 处理方式 |
| --- | --- |
| 官方版本更新，但两处判断仍符合已知结构 | 自动重建副本，不必重写补丁。 |
| Node.js、解析器或保存的本机路径失效 | 修复依赖并重新开启自动重建，不修改权限判断规则。 |
| 官方改变了界面或请求判断结构 | 让 agent 针对已安装版本分析并适配，再执行回归和启动验证。 |
| 构建通过、按钮可选，但没有实际提速 | 检查请求档位、模型和服务商支持，不以强行显示按钮作为解决办法。 |

已遇到的例子：`26.1013.4894.0` 将布尔判断改为 `serviceTierAccess`，需要补丁引擎 v2；
`26.1016.8120.0` 扩展了官方认证名单，需要 v3。两次都保留了既有补丁框架，修改的是
相关识别规则。**每个新版本需要验证，只有不兼容的结构变化才需要新增适配。**

### 解决步骤

1. 记录当前官方包版本、实际启动的程序路径，以及
   `%USERPROFILE%\.codex-api-fast-client\auto-update-status.json` 的状态和错误原因。
   先区分旧副本、依赖缺失与未知代码结构；诊断材料不应包含凭据或聊天内容。
2. 若结构兼容，恢复依赖或重建即可。修复依赖后可再次运行
   `Enable-LocalApiFastAutoUpdate.ps1` 清除失败记录并开启重试，再从桌面切换器进入 API 账户。
3. 若出现未知结构，让 agent 只读分析该版本 `resources\app.asar` 内的客户端代码，
   追踪 Fast 的界面判断、请求档位处理和权限函数之间的关系。修改 `patch-core.cjs`
   的语义识别规则，不能只写死某个压缩变量名或替换按钮文本。
4. 为新结构增加回归：API Key 的界面和请求判断均可通过；原有登录方式、加载状态、
   模型支持和管理员限制保持原意。同时检查旧版本规则仍可用，以及未知、重复或只改一半的
   结构会被拒绝。执行下方“验证”中的测试命令。
5. 在本地副本中应用修改，重新生成 ASAR 与启动器的对应校验值。验证原包未被修改，
   安装清单指向当前版本，并使用隔离配置验证实际启动。重开真实客户端后再确认 Fast
   可选与请求档位传递；若没有检查实际请求或服务端速度，应明确标为未验证。

不要把关闭完整性检查、强行放行所有身份或删除全部版本目录作为兼容方案。
已有安装器负责临时构建、完整性校验、原子发布和失败恢复，适配时应继续使用它。

### 可直接交给 agent 的任务说明

> 请检查本机当前 Codex 官方版本在 API Key 登录下的 Fast 兼容性。先阅读本项目的
> `tools/codex-api-fast` 实现与更新状态，判断是旧副本、依赖问题还是官方代码结构变化。
> 已知结构只需重建；未知结构请分析当前版本安装包，同时适配 Fast 的界面和请求判断，
> 保留模型支持、加载状态及管理员限制，增加能复现本次问题的回归测试，并验证旧规则。
> 使用现有安装器生成本地副本，保持官方原包不变，检查校验值与隔离启动结果。
> 不读取或输出我的密钥、聊天内容，不自动发送付费请求。报告验证过的官方版本、修改点、
> 测试结果，以及按钮、请求档位和实际加速分别验证到了哪一步；不要宣称任意未来版本都兼容。

## 改动与限制

- 检查原版启动器的 OpenAI 签名；只修改副本的两处 Fast 认证判断。
- 更新副本启动器内的 ASAR 预期哈希，并调整依赖商店环境的私有程序集声明。
  运行库和 Electron fuse 不变，ASAR 完整性校验保持开启。
- 修改后的启动器不再有有效的 OpenAI Authenticode 签名，属于用户本地修改版。
- 共用原有 `.codex` 登录、会话和项目，显式使用商店版的桌面浏览器数据目录。
  不支持原版和修改版同时使用这些数据。
- 副本没有商店包身份，内置更新器不可用；原版由 Microsoft Store 更新。
  其他依赖包身份的功能未全面验收。

每次启动检查商店版本，以及副本的 EXE、ASAR、运行库哈希。启用自动适配后，
不一致时先尝试重建；未开启或适配失败时提示并回到官方版。
也可手动运行 `Rebuild-LocalApiFastClient.cmd`。安装器串行构建到临时目录，完整
验证后才原子切换清单；失败保留旧清单，已有未知目录移入 quarantine 留供排查。
中断后已完成的版本可通过其独立清单验证并恢复，失败构建保留供排查。

停用：运行 `Disable-LocalApiFastClient.ps1`，退出 Codex 后重新打开切换器。
它同时关闭自动适配并停用安装清单，保留副本以便检查。不要再运行旧版写入 WindowsApps 的修复脚本。
