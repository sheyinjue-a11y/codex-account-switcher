# Astra 首条消息预热设计

## 用户已确认的目标

在官方 Codex 新会话中直接选择 Astra 并提交第一条消息：提交前先以 `gpt-5.6-sol`、`low` 完成一次最小预热请求，再让 Codex 按原来的 Astra 模型和推理设置发送原消息。失败明确提示，不静默降级，不要求用户手动换模型。Windows 与 macOS 一起交付。

## 范围与边界

- 不修改项目或工作区，不修改官方 Codex 安装包，不伪造模型权限。
- 模型列表来自本机官方 `models_cache.json`；每次激活 API 档时更新切换器快照，保留完整元数据、自定义目录、隐藏状态及已选模型。缓存异常回退。它不是联网即时同步，官方 Codex 必须先刷新本地目录。
- 预热仅支持 Responses API 的文件登录。默认关闭，每个 API 端点及凭据组合独立启用；更换 Key 后需重新启用。ChatGPT 登录不调用预热。
- 采用官方 `UserPromptSubmit` 同步命令钩子，不接管桌面发送按钮。用户必须在 Codex 审核并信任钩子，升级后可能需要重新信任；工具不绕过此步骤。
- 开启时说明新增请求可能收费。仅每个会话、每个已启用 API 凭据组合首次提交 `gpt-6-astra` 时执行一次。其他模型不触发；用户取消、失败或超时不记成功。
- 预热是独立 Responses 请求，不声称与随后 Astra 共用 TCP/WebSocket。是否能解决特定服务的冷启动问题必须另行验收。

## 数据与控制流

1. 切换器提供“当前 API 的 Astra 自动预热”启用/关闭入口，核对当前文件登录与配置。保存非秘密授权指纹，不另存明文 Key。
2. 以保留未知字段及其他钩子的方式合并用户级 `hooks.json`，仅维护本工具标识的处理器。拒绝损坏配置或不安全链接，不写项目配置。
3. 钩子从标准输入读取事件，只接受 `UserPromptSubmit`、有效会话标识和 `gpt-6-astra`。读取当前用户默认 Codex 文件登录与路由；仅对用户明确启用的端点/Key 指纹生效。
4. 并发保护确保同一会话不重复预热。请求仅发往当前已授权端点，TLS 正常验证、禁止跨站重定向；不监听外部端口，不记录 Key、用户原消息或响应全文。
5. 固定输入为最小确认消息，模型为 `gpt-5.6-sol`，推理为 `low`，无工具、附件或工作区上下文，限制输出及总等待时间。只有完整成功响应才标记会话已预热。
6. 成功后钩子正常退出，原消息原样由 Codex 继续交给 Astra；失败返回官方阻止消息的结构化结果并给出安全可理解的原因。用户可重试或关闭预热，不自动无限重试。
7. 状态存放在切换器自身用户数据目录，支持多窗口隔离和跨进程去重。账户切换不将上一账号预热状态用于下一账号。

## 跨平台实现约束

Windows 继续使用 PowerShell 5.1/WPF；macOS 使用现有 Swift 应用增加非 GUI 钩子入口。日常使用不新增 Python/Node 依赖。所有真实网络请求仅由启用后的用户行为触发；自动测试使用假凭据和本地回环服务。

## 验收与发布

- 自动化验证：Sol/low 先于原始 Astra 请求，原消息未被改写；第二条消息无重复预热；其他模型/未启用/ChatGPT 无请求；失败阻止 Astra；并发去重；服务切换隔离；超时、错误 SSE/JSON、重定向、秘密脱敏；其他钩子保留及安全卸载。
- 使用隔离官方 app-server 验证钩子顺序与实际阻止行为，不把单元测试通过视为真实服务兼容性证明。
- Windows 全套离线回归及 macOS Swift/双架构/签名检查通过后，更新 README、CHANGELOG、版本和 Release 说明。发布 Windows ZIP、macOS Universal ZIP 和 SHA256 校验文件。
- 保留现有 macOS ad-hoc 签名、未经公证及真实桌面人工验收的限制说明。
- 未验证的服务兼容性明确披露；不声称官方 Astra 本身要求 Sol 预热。
