# 模型目录自动更新设计与验收

目标：在 Windows / macOS 复用已发布 v0.3.0 的模型目录同步机制，支持 `gpt-6.1-sol` 和未来模型，额外在打开切换器时刷新已有目录。

## 已有设计

官方 Codex 更新并刷新共享目录 `models_cache.json` → 用户退出 Codex 并激活 API 档 → 校验完整列表 → 原子更新切换器模型快照 → Codex 启动读取。

已有托管目录还支持：官方缓存更新 → 打开切换器 → 在账号库互斥锁内校验并刷新快照。这个入口不改认证、配置或账号库，首次绑定仍交给激活事务；未完成恢复、忙锁、缺失或坏缓存时跳过。普通只读 Status 不触发刷新，Windows 图形界面的 List 显式请求刷新；macOS 在 GUI reload 中调用最佳努力刷新。

- 没有固定模型名称白名单，不复制其他模型冒充新模型。保留完整记录、排序、隐藏标记、能力、上下文和说明，不强改用户选定模型。
- Windows 托管 `api-models.json` 与旧实验室 `lab-models.json`；macOS 托管 `api-models.json`。官方缓存及用户自定义目录不改写。
- 缓存损坏、空列表、重复名称、无可见 API 模型时保留上次有效目录；没有有效目录时不写无效覆盖路径。不变内容不重写。
- 账号库互斥锁及原有切换事务保护快照；切换失败恢复凭据、配置和原目录，中断由原有恢复流程处理。
- 不额外联网、不轮询、不发送付费模型探测、不启动常驻服务。打开切换器和激活 API 档时触发，无需每次为新模型发布代码。
- 官方更新不等于缓存已刷新；一直使用 API 登录而没有新缓存时，先用官方账号让 Codex 更新缓存。已打开的模型菜单不保证热更新。模型能否调用取决于服务商支持。

## 本次实施

1. 本机备份旧目录，按原方法同步官方缓存的完整记录；核验包含 `gpt-6.1-sol`，auth/config 哈希保持不变。
2. 将 GitHub v0.3.0 的动态模型同步逻辑同步到本机，保留本地未提交工作和修好的包启动入口。
3. 两端补 6.1 / 未来模型回归，验证元数据与当前模型保留、不变内容不重写；验证窗口刷新保持 auth/config/账号库不变且避让恢复记录；沿用已有损坏缓存、自定义目录与回滚测试。
4. Windows 公开版同步本机已验证的 MSIX 包激活修复及测试。
5. Windows 本地测试、GitHub Windows/macOS CI、同一提交构建的 v0.3.1 预览包。
